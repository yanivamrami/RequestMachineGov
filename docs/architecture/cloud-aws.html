Requests platform: AWS deployment

Part C sketch for massive scale: hundreds of millions of requests, ~5k API calls/s and event bursts of 10k/s. Everything runs in one region across 3 Availability Zones, with a warm standby region for disaster recovery. Pick a flow to highlight it, and hover over any box for details. The reasoning is in cloud-aws.md.

Compute

  • ECS on Fargate, one service per microservice, tasks spread over 3 AZs in private subnets
  • ALB with path routing; CloudFront + WAF at the edge; SPA served from S3
  • Service Connect for internal sync REST calls
  • Workers (Notifications, Reporting) scale separately from the APIs

DB

  • Aurora PostgreSQL per service, behind RDS Proxy
  • Requests: searches go to auto-scaled readers (2–15); monthly partitions on CreatedAt; pg_trgm for partial number search
  • DynamoDB for Notifications: a conditional put = dedupe
  • S3 for documents (pre-signed URLs); Redis for idempotency keys

Messaging

  • SNS topic per event type, fanning out to an SQS queue per consumer
  • Retry ladder: 3 in-process tries per receive, then ChangeMessageVisibility backoff of 1m/5m/30m/2h
  • Redrive to a DLQ after 5 receives; standard queues, ordering handled by version
  • MassTransit SQS transport; RabbitMQ locally

Monitoring

  • CloudWatch logs (JSON + correlationId), Container Insights
  • OpenTelemetry → X-Ray: one trace runs from HTTP → outbox → SQS → SES
  • Alarms: DLQ > 0, age of the oldest queued message, outbox lag, 5xx/p99, circuit breaker open, Aurora lag → PagerDuty

Scaling

  • APIs: target tracking on ALB requests per target and CPU
  • Workers: SQS backlog per task (~100); scale out on bursts, back to the minimum when idle
  • Aurora reader auto-scaling; DynamoDB on-demand; SNS/SQS/S3 managed
  • Consumer concurrency limits act as back-pressure on the DBs and SES

Availability & DR

  • Multi-AZ everywhere; Aurora failover typically under 30s
  • Standby region: Aurora Global DB, DynamoDB global tables, S3 replication, Route 53 failover
  • RPO ≈ seconds, RTO ≈ 15–30 min (active-passive)
